# Supabase для WasteWise — пошагово

**Что получится:** аккаунты, баллы и история хранятся в Supabase (бесплатный Postgres в облаке) и больше не стираются, когда Streamlit Cloud перезапускает сайт.
**Время:** ~15 минут. **Локально** ничего настраивать не нужно: без строки подключения сайт, как и раньше, хранит всё в файле `data/app.db`.

---

## Шаг 1. Создать проект Supabase
1. Откройте [supabase.com](https://supabase.com) → **Start your project** → войдите через GitHub.
2. **New project**:
   - **Organization** — любая (план **Free**).
   - **Project name** — `wastewise`.
   - **Database Password** — нажмите **Generate a password** и **сохраните его** (понадобится в шаге 2). Удобнее пароль только из букв и цифр: символы `@ : / ? # %` в строке подключения нужно кодировать.
   - **Region** — ближе к серверу сайта, а не к пользователям: с базой общается сервер Streamlit. Серверы Streamlit Community Cloud — в США, поэтому подойдёт, например, **East US (North Virginia)**.
   - Остальное оставьте по умолчанию.
3. **Create new project** и подождите 1–2 минуты, пока проект создаётся.

## Шаг 2. Взять строку подключения — Session pooler
1. В проекте нажмите кнопку **Connect** вверху страницы.
2. Выберите **Connection String** → тип **URI** → способ **Session pooler**.
   - ❌ Не **Direct connection**: адрес `db.<id>.supabase.co` работает только по IPv6, а у Streamlit Cloud и GitHub Actions IPv6 нет — сайт не подключится.
   - ❌ Не **Transaction pooler** (порт `6543`).
3. Скопируйте строку. Она выглядит так:
   ```
   postgresql://postgres.abcdefghijklmnop:[YOUR-PASSWORD]@aws-0-us-east-1.pooler.supabase.com:5432/postgres
   ```
   Проверьте три признака: пользователь `postgres.<id проекта>`, хост `…pooler.supabase.com`, порт **5432**.
4. Замените `[YOUR-PASSWORD]` **вместе со скобками** на пароль из шага 1.
   Забыли пароль → **Project Settings → Database → Reset database password**.

> ⚠️ Эта строка — полный доступ к базе. Не публикуйте её и не коммитьте в репозиторий. Если она утекла: **Reset database password** и обновите строку в шагах 3 и 5.

## Шаг 3. Вставить строку в Streamlit Cloud
1. [share.streamlit.io](https://share.streamlit.io) → ваше приложение → **⋮** → **Settings** → **Secrets**.
2. Добавьте строку (это формат TOML — кавычки обязательны):
   ```toml
   DATABASE_URL = "postgresql://postgres.abcdefghijklmnop:ВАШ_ПАРОЛЬ@aws-0-us-east-1.pooler.supabase.com:5432/postgres"
   ```
   Если там уже есть `OPENAI_API_KEY` — оставьте его, просто добавьте строку ниже.
3. **Save changes**. Сайт перезапустится примерно за минуту (если нет — **⋮ → Reboot app**).

Таблицы создавать не нужно: при первом запуске сайт сам применит SQL-миграции из `supabase/migrations/`.

## Шаг 4. Проверить
1. Откройте сайт → зарегистрируйтесь → распознайте фото.
2. Supabase → **Table Editor**: появились таблицы `users`, `scans`, `quiz_results`, `schema_migrations`. В `users` — ваш аккаунт, а в столбце `password` — строка вида `pbkdf2$…$…`: это хэш, самого пароля в базе нет.
3. Streamlit Cloud → **⋮ → Reboot app** → войдите тем же логином: аккаунт и баллы на месте. ✅
4. Supabase → **Advisors → Security Advisor**: предупреждения «RLS disabled» быть не должно — защита таблиц включена миграцией.

**Если на сайте «Не удалось подключиться к базе данных»** — под сообщением будет подсказка. Частые причины:
- не заменили `[YOUR-PASSWORD]`;
- взяли Direct connection вместо Session pooler;
- в пароле есть `@ : / ? # %` — смените пароль на буквы и цифры (шаг 2, п. 4) или закодируйте символ (`@` → `%40`);
- проект на паузе — см. шаг 5.

Подробности ошибки — в логах: Streamlit Cloud → **Manage app** (внизу справа на сайте).

## Шаг 5. Keep-alive: чтобы бесплатный проект не уходил на паузу
Бесплатный проект Supabase ставится на паузу после недели без запросов. Данные сохраняются, но сайт не откроет базу, пока проект не включить вручную (Supabase → проект → **Restore project**). Workflow `supabase-keepalive` раз в 2 дня делает простой запрос к таблице `users`.

1. GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
2. **Name:** `SUPABASE_DATABASE_URL`, **Secret:** та же строка, что в шаге 3 (без кавычек) → **Add secret**.
3. После слияния PR в `main`: **Actions → supabase-keepalive → Run workflow**. Через минуту запуск должен стать зелёным, а в логе — «Supabase ответил — база активна».

Дальше он запускается сам. Что важно знать:
- GitHub запускает расписание только из ветки `main` — до слияния PR keep-alive не работает.
- В публичном репозитории GitHub отключает расписание, если 60 дней не было коммитов (придёт письмо). Включить снова: **Actions → supabase-keepalive → Enable workflow**.
- Таблицы к этому моменту должны существовать — откройте сайт хотя бы раз (шаг 4).
- Сам вывод в логах безопасен: скрипт не печатает ни пароль, ни адрес базы.

## Дополнительно

**Создать таблицы вручную** (необязательно). Supabase → **SQL Editor → New query** → вставьте по очереди файлы из `supabase/migrations/` (по порядку имён) → **Run**. Повторный запуск безопасен.

**Supabase на своём компьютере.** Скопируйте `.streamlit/secrets.toml.example` в `.streamlit/secrets.toml` и раскомментируйте `DATABASE_URL` (этот файл в git не попадает). Без него — локальный `data/app.db`.

**Тесты на Postgres.** `pytest` всегда проверяет SQLite. Если задать `TEST_DATABASE_URL`, те же тесты пойдут и на Postgres. ⚠️ Укажите там **отдельную тестовую базу**: перед каждым тестом она очищается. На GitHub это делается автоматически (контейнер Postgres 15 и 17).

**Что пока не в Supabase.** Фото из кнопки «Модель ошиблась» (`data/feedback/`) по-прежнему сохраняются на диск сервера, и на Streamlit Cloud они стираются при перезапуске. Следующий шаг — Supabase Storage.

**Старые аккаунты.** Аккаунты, созданные на сайте до подключения Supabase, не переносятся: они хранились в `data/app.db` на сервере Streamlit и всё равно стирались при каждом перезапуске.

**Лимиты бесплатного плана.** 500 МБ базы. Одна запись о распознавании — порядка сотни байт, так что места хватит надолго.

**Как это устроено в коде.**
- `core/pg.py` — подключение через psycopg и применение миграций;
- `core/db.py` — функции хранилища, одинаковые для SQLite и Postgres;
- `supabase/migrations/` — таблицы. В них включён RLS: публичный REST API Supabase не видит ни одной строки, а сайт работает как владелец таблиц.
