# ♻️ WasteWise — сортировка отходов с помощью ИИ

Веб-приложение: фотографируешь мусор, нейросеть определяет тип отхода (стекло, металл, бумага, пластик) и показывает, куда его выбросить и что НЕ принимают. Есть викторина, баллы и рейтинг школ.

Автор проекта: Адильжан Кадыргажы (Астана) — [Telegram](https://t.me/crybaby_c) · [Instagram](https://www.instagram.com/_kadyrgazhy_a)

## Что изменено и почему
Аудит кода, октябрь 2026. Каждое изменение — отдельный коммит, весь прежний функционал сохранён.

### 1. Распознавание стало быстрее и не падает на «плохих» файлах
- **Было.** Streamlit перезапускает код страницы при *любом* клике — даже при выборе пункта в списке «Правильный тип». И каждый раз обе нейросети заново обрабатывали то же самое фото. Снимок с телефона (12 Мп) шёл в обработку целиком. Файл, который не открывается как картинка, показывал красную ошибку Python.
- **Стало.** Результат запоминается для каждого фото (по «отпечатку» файла) — повторные клики мгновенные. Большие фото уменьшаются до 1280 px: нейросетям этого хватает (они всё равно работают на 224–640 px), а памяти нужно в разы меньше (фото для дообучения в `data/feedback/` тоже сохраняются в этом размере — для обучения на 224 px хватает с запасом). Битый файл → понятное сообщение.
- **Где в коде:** `core/model.py` → `load_image`; `app.py` → `cached_check_scene`, `cached_classify`.

### 2. Баллы за одно и то же фото — только один раз
- **Было.** Приложение помнило только *последнее* фото. Чередуя два снимка (А → Б → А → Б…), можно было бесконечно получать +10 за распознавание и +15 за «исправление» — и нечестно подняться в рейтинге школ.
- **Стало.** Сайт помнит все фото, проверенные в этом окне браузера, а у вошедшего пользователя ещё и сверяется с базой (выход и повторный вход не помогают). При повторе показывается «Это фото вы уже проверяли».
- **Где в коде:** `app.py` (блок «Одно и то же фото не даёт баллы повторно»), `core/db.py` → `find_scan`, столбец `scans.image_hash`. Старая база дополняется новым столбцом сама при запуске.
- **Честно:** это защита от простой накрутки. Обрезанное или пересохранённое фото считается новым. Баллы за викторину пока без лимита.

### 3. Сайт не сбоит, когда им пользуются одновременно
- **Было.** Соединение с базой и нейросети — одни на всех посетителей, а Streamlit обслуживает посетителей параллельно. Проверка «16 учеников в одну секунду» на старом коде: ошибки базы, потерянные баллы, а одновременная регистрация одного логина роняла страницу.
- **Стало.** Запросы к базе и к нейросетям идут по очереди, как к одному окошку. Та же проверка: 0 ошибок, все баллы на месте, при занятом логине — сообщение «Такой логин уже занят». Медленная проверка пароля выполняется вне очереди, чтобы не задерживать остальных.
- **Где в коде:** `core/db.py` → `_LOCK`, `_locked`; `core/model.py` → `_PREDICT_LOCK`.

### 4. Найдено при проверке: свежая установка ломала распознавание
- **Было.** В `requirements.txt` версия OpenCV не была указана, и сейчас вместе с ultralytics ставится OpenCV 5. В нём убрали детектор лиц `cv2.CascadeClassifier`, и на новой установке (в том числе на Streamlit Cloud) страница распознавания падала с ошибкой.
- **Стало.** `opencv-python>=4.6,<5`. Если детектора лиц всё же нет, проверка лица пропускается, а людей в кадре по-прежнему отсекает YOLO-детектор.
- **Где в коде:** `requirements.txt`, `core/model.py` → `_has_face`.

### Как проверить
```bash
pip install -r requirements.txt pytest
pytest
```
17 тестов в `tests/`, около 20 секунд. Нейросети в них заменены «поддельными», поэтому тесты не зависят от torch и проверяют логику приложения: кэш, баллы, очередь к базе и моделям. На исходном коде эти же тесты падают: 30 баллов вместо 20, повторное «исправление», ошибки базы при 16 параллельных пользователях.

## Структура
```
app.py              ← весь интерфейс (страницы сайта)
core/content.py     ← тексты: советы по утилизации, вопросы викторины, баллы
core/model.py       ← нейросеть: загрузка и распознавание
core/db.py          ← база данных: пользователи, баллы, история
core/quiz.py        ← викторина (готовые вопросы + ИИ)
assets/             ← модель best.pt, логотип, картинка
samples/            ← тестовые фото
train/              ← скрипт переобучения на YOLO26
tests/              ← автотесты (pytest), нейросети в них «поддельные»
data/               ← создаётся сам: база app.db и фото-исправления (в git не попадает)
```

## Запуск на компьютере (Windows)
```bash
cd "waste project v2"
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```
Откроется http://localhost:8501. Для ИИ-викторины скопируйте `.env.example` в `.env` и вставьте ключ OpenAI.

## Выложить в интернет (получить ссылку)
1. Создать репозиторий на GitHub и загрузить туда эту папку (`.env` не загрузится — так и надо).
2. Зайти на share.streamlit.io → New app → выбрать репозиторий → файл `app.py`.
3. В настройках приложения → Secrets добавить: `OPENAI_API_KEY = "ваш ключ"`.

⚠️ На бесплатном Streamlit Cloud база `data/app.db` стирается при перезапуске. Для постоянного рейтинга позже нужна внешняя база (например, Supabase).

## Ограничения (честно)
- Модель знает только 4 класса, обучена на ~450 фото (top-1 точность 91,8% на тестовой выборке).
- Это классификация: один предмет на фото. Если на фото куча разного мусора — ответ будет неточным.
- Ultralytics распространяется под лицензией AGPL-3.0: для коммерческого закрытого продукта нужна платная лицензия.
