# ♻️ WasteWise — сортировка отходов с помощью ИИ

Веб-приложение: фотографируешь мусор, нейросеть определяет тип отхода (стекло, металл, бумага, пластик) и показывает, куда его выбросить и что НЕ принимают. Есть викторина, баллы и рейтинг школ.

Автор проекта: Адильжан Кадыргажы (Астана) — [Telegram](https://t.me/crybaby_c) · [Instagram](https://www.instagram.com/_kadyrgazhy_a)

## Что изменено и почему
Аудит кода, октябрь 2026. Каждое изменение — отдельный коммит, весь прежний функционал сохранён.

### 1. Распознавание стало быстрее и не падает на «плохих» файлах
- **Было.** Streamlit перезапускает код страницы при *любом* клике — даже при выборе пункта в списке «Правильный тип». И каждый раз обе нейросети заново обрабатывали то же самое фото. Снимок с телефона (12 Мп) шёл в обработку целиком. Файл, который не открывается как картинка, показывал красную ошибку Python.
- **Стало.** Результат запоминается для каждого фото (по «отпечатку» файла) — повторные клики мгновенные. Большие фото уменьшаются до 1280 px: нейросетям этого хватает (они всё равно работают на 224–640 px), а памяти нужно в разы меньше (фото для дообучения в `data/feedback/` тоже сохраняются в этом размере — для обучения на 224 px хватает с запасом). Битый файл → понятное сообщение.
- **Где в коде:** `core/model.py` → `load_image`; `app.py` → `cached_check_scene`, `cached_classify`.

### 2. Баллы за одно и то же фото — только один раз
- **Было.** Приложение помнило только *последнее* фото. Чередуя два снимка (А → Б → А → Б…), можно было бесконечно получать +10 за распознавание и +15 за «исправление» — и нечестно подняться в рейтинге школ.
- **Стало.** Сайт помнит все фото, проверенные в этом окне браузера, а у вошедшего пользователя ещё и сверяется с базой (выход и повторный вход не помогают). При повторе показывается «Это фото вы уже проверяли».
- **Где в коде:** `app.py` (блок «Одно и то же фото не даёт баллы повторно»), `core/db.py` → `find_scan`, столбец `scans.image_hash`. Старая база дополняется новым столбцом сама при запуске.
- **Честно:** это защита от простой накрутки. Обрезанное или пересохранённое фото считается новым. Лимит баллов за викторину — в пункте 7.

### 3. Сайт не сбоит, когда им пользуются одновременно
- **Было.** Соединение с базой и нейросети — одни на всех посетителей, а Streamlit обслуживает посетителей параллельно. Проверка «16 учеников в одну секунду» на старом коде: ошибки базы, потерянные баллы, а одновременная регистрация одного логина роняла страницу.
- **Стало.** Запросы к базе и к нейросетям идут по очереди, как к одному окошку. Та же проверка: 0 ошибок, все баллы на месте, при занятом логине — сообщение «Такой логин уже занят». Медленная проверка пароля выполняется вне очереди, чтобы не задерживать остальных.
- **Где в коде:** `core/db.py` → `_LOCK`, `_locked`; `core/model.py` → `_PREDICT_LOCK`.

### 4. Найдено при проверке: свежая установка ломала распознавание
- **Было.** В `requirements.txt` версия OpenCV не была указана, и сейчас вместе с ultralytics ставится OpenCV 5. В нём убрали детектор лиц `cv2.CascadeClassifier`, и на новой установке (в том числе на Streamlit Cloud) страница распознавания падала с ошибкой.
- **Стало.** `opencv-python>=4.6,<5`. Если детектора лиц всё же нет, проверка лица пропускается, а людей в кадре по-прежнему отсекает YOLO-детектор.
- **Где в коде:** `requirements.txt`, `core/model.py` → `_has_face`.

### 5. Тесты запускаются на GitHub сами
- **Было.** Тесты нужно было не забыть запустить вручную.
- **Стало.** При каждом push и pull request GitHub Actions запускает `pytest`. Это около минуты: нейросети в тестах «поддельные», и torch не ставится. Ошибку видно в PR до того, как код попадёт на сайт.
- **Где:** `.github/workflows/tests.yml`, `requirements-test.txt`.

### 6. Подготовка к следующим версиям Streamlit
- **Было.** `use_container_width=True` у картинок, таблиц и графиков. Streamlit пометил этот параметр устаревшим и удалит его в одной из следующих версий — тогда страницы сломались бы.
- **Стало.** `width="stretch"` — то же самое по-новому. У графиков он появился только в Streamlit 1.51, поэтому в `requirements.txt` теперь `streamlit>=1.51`. Проверено на 1.51 и 1.65.

### 7. Лимит баллов за викторину: 3 викторины в сутки
- **Было.** За викторину баллы давались без ограничений. Готовых вопросов всего 12 — их быстро запоминают, а ИИ-режим составит вопросы по любому своему тексту. Рейтинг можно было выиграть, ни разу не сфотографировав мусор.
- **Стало.** Баллы дают только за первые 3 викторины за последние 24 часа (оба режима вместе). Викторина с 0 правильных ответов лимит не тратит. Тренироваться без баллов можно сколько угодно. На странице видно, сколько викторин с баллами осталось. В профиле появился столбец «Баллы».
- **Почему так.** Правило простое и понятное школьнику. Оно одинаково работает для готовых и ИИ-вопросов: «баллы за каждый вопрос один раз» не подошло бы — ИИ-вопросы каждый раз новые. Учиться дальше лимит не мешает, а возвращаться каждый день — стимулирует. Окно «24 часа», а не «до полуночи»: сервер живёт по UTC, и его полночь в Астане — это 5 утра.
- **Где в коде:** `core/content.py` → `QUIZ_REWARDS_PER_DAY`; `core/db.py` → `rewarded_quizzes_last_day`, столбец `quiz_results.points` (старая база дополняется сама, прошлые баллы восстанавливаются).

### 8. Мелкая ошибка: пропадали баллы в меню
- **Было.** Если фото отклонял фильтр «не мусор» (например, в кадре человек), из бокового меню пропадала строка «👤 Имя · ⭐ баллы».
- **Стало.** Строка видна всегда. **Где:** `app.py` → `show_points`.

### 9. Сборка torch без видеокарты: теперь проверяется
- `--extra-index-url https://download.pytorch.org/whl/cpu` в `requirements.txt` был и раньше. Благодаря ему ставится torch для процессора (~200 МБ), а не версия для видеокарт (+2–3 ГБ, на сервере Streamlit Cloud без GPU бесполезна).
- **Новое:** при изменении `requirements.txt` GitHub проверяет без установки, что pip и uv действительно выбирают сборки `+cpu`, не тянут CUDA-библиотеки и ставят OpenCV < 5 (`.github/workflows/requirements.yml`). Первый прогон: и pip, и uv берут `torch 2.14.1+cpu`, `torchvision 0.29.1+cpu`, `opencv-python 4.14`.
- **Попутная находка:** uv (в отличие от pip) берёт `requests`, `urllib3` и `certifi` из индекса PyTorch, а там лежат версии 2022 года (`requests 2.28.1`, `urllib3 1.26.13`) с известными уязвимостями, например CVE-2023-32681. Проверка показывает это предупреждением. Что делать — в таблице ниже.
- **Честно:** на самом Streamlit Cloud это не проверялось.

### 10. Аккаунты и баллы больше не стираются: база в Supabase
- **Было.** Всё хранилось в файле `data/app.db` на сервере Streamlit Cloud, а он стирается при каждом перезапуске сайта: ученики теряли аккаунты, школы — баллы.
- **Стало.** На сайте база — Supabase (бесплатный Postgres в облаке). Подключение — через Session pooler, строка подключения — в Secrets Streamlit Cloud (в коде и в репозитории её нет). Таблицы описаны SQL-миграциями в `supabase/migrations/`, сайт применяет их сам при запуске. Локально и в тестах — по-прежнему файл SQLite, ничего настраивать не нужно.
- **Пароли.** Регистрация та же: в базе только хэш PBKDF2 с солью, а Supabase вдобавок проверкой `CHECK` не примет пароль открытым текстом. Старые хэши sha256 без соли (версия 1) заменяются на PBKDF2 при входе.
- **Защита.** Публичный REST API Supabase таблиц не видит (RLS). Если связь с базой оборвалась — сайт сам переподключается; если база недоступна — показывает понятное сообщение, а не ошибку Python.
- **Keep-alive.** Бесплатный Supabase засыпает после недели без запросов, поэтому GitHub раз в 2 дня делает к нему простой запрос (`.github/workflows/supabase-keepalive.yml`).
- **Как подключить — пошагово:** [docs/SUPABASE.md](docs/SUPABASE.md).
- **Где в коде:** `core/pg.py` (подключение, миграции), `core/db.py` (общие функции для обеих баз), `app.py` → `get_db`.

### Как проверить
```bash
pip install -r requirements-test.txt   # без torch, ~1 минута
pytest
```
Около 30 секунд. Нейросети в тестах заменены «поддельными», поэтому тесты проверяют логику приложения: кэш, баллы, лимит викторины, очередь к базе и моделям, пароли, все страницы. На исходном коде эти тесты падают: 30 баллов вместо 20, повторное «исправление», ошибки базы при 16 параллельных пользователях.

Тесты базы и сквозные сценарии идут на SQLite, а если задан `TEST_DATABASE_URL` — ещё и на Postgres (⚠️ только отдельная тестовая база: она очищается). На GitHub всё запускается само, на Postgres 15 и 17 (пункт 5).

## Структура
```
app.py              ← весь интерфейс (страницы сайта)
core/content.py     ← тексты: советы по утилизации, вопросы викторины, баллы
core/model.py       ← нейросеть: загрузка и распознавание
core/db.py          ← база данных: пользователи, баллы, история (SQLite локально, Postgres на сайте)
core/pg.py          ← подключение к Supabase (Postgres) и применение миграций
core/quiz.py        ← викторина (готовые вопросы + ИИ)
assets/             ← модель best.pt, логотип, картинка
samples/            ← тестовые фото
train/              ← скрипт переобучения на YOLO26
supabase/migrations ← таблицы для Supabase (SQL), сайт применяет их сам
docs/SUPABASE.md    ← как подключить Supabase — пошагово
tests/              ← автотесты (pytest), нейросети в них «поддельные»
.github/            ← GitHub Actions: тесты, состав requirements.txt, keep-alive для Supabase
data/               ← создаётся сам: локальная база app.db и фото-исправления (в git не попадает)
```

## Запуск на компьютере (Windows)
```bash
cd "waste project v2"
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```
Откроется http://localhost:8501. Для ИИ-викторины скопируйте `.env.example` в `.env` и вставьте ключ OpenAI.

## Выложить в интернет (получить ссылку)
1. Создать репозиторий на GitHub и загрузить туда эту папку (`.env` не загрузится — так и надо).
2. Зайти на share.streamlit.io → New app → выбрать репозиторий → файл `app.py`.
3. В настройках приложения → Secrets добавить: `OPENAI_API_KEY = "ваш ключ"`.
4. Чтобы аккаунты и баллы не стирались при перезапуске: подключить Supabase и добавить в Secrets `DATABASE_URL` — пошагово в [docs/SUPABASE.md](docs/SUPABASE.md). Без этого Streamlit Cloud стирает базу `data/app.db` при каждом перезапуске.

## Ограничения (честно)
- Модель знает только 4 класса, обучена на ~450 фото (top-1 точность 91,8% на тестовой выборке).
- Это классификация: один предмет на фото. Если на фото куча разного мусора — ответ будет неточным.
- Ultralytics распространяется под лицензией AGPL-3.0: для коммерческого закрытого продукта нужна платная лицензия.
